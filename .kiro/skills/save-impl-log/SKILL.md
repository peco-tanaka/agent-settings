# Save Implementation Log - 実装ログ保存スキル

実装内容をテンプレートに沿って `.kiro/logs/` にmarkdownファイルとして記録する。

## テンプレート

`assets/template.md` を読み込み、プレースホルダーを実際の値で置き換えて使用する。

| プレースホルダー | 内容                                               |
| ---------------- | -------------------------------------------------- |
| `{{TASK_TITLE}}` | タスクのタイトル                                   |
| `{{DATE}}`       | 当日の日付（YYYY-MM-DD）                           |
| `{{PLAN_REF}}`   | 対応するplanファイルへの相対パス。なければ「なし」 |

各セクションの内容は、セッション中の実装内容に基づいて具体的に記述する。

## ワークフロー

### Step 1: ディレクトリの準備

`.kiro/logs/` ディレクトリが存在しない場合、作成する。

```bash
mkdir -p .kiro/logs
```

### Step 2: planファイルの確認

`.kiro/plans/` 内に現在のタスクに対応するplanファイルがあるか確認する。

- 存在する場合: `{{PLAN_REF}}` に相対パスを設定（例: `../plans/2026-02-01_add-auth.md`）
- 存在しない場合: `{{PLAN_REF}}` に「なし」を設定

### Step 3: テンプレートの読み込みと記入

`assets/template.md` を読み込み、プレースホルダーを置き換えた上で、各セクションをセッション中の実装内容に基づいて記入する。

記入ルール:

- **日本語**で記載する
- **目的**: タスクで達成したかったことを簡潔に記述
- **実施内容**: 何を削除し、何を追加したか具体的に記述
- **変更ファイル一覧**: 実際に変更したファイルパスをすべて列挙
- **設計判断**: なぜその方法を選んだか、検討した選択肢と理由を明記
- **備考**: 補足事項があれば記述、なければセクションごと省略可

### Step 4: ファイル名の決定と保存

```text
.kiro/logs/YYYY-MM-DD_task-name.md
```

- `YYYY-MM-DD`: 当日の日付
- `task-name`: タスクの概要をkebab-caseで簡潔に表現（英語、3-5語程度）
- 同名ファイルが存在する場合、末尾に連番を付与する（例: `_2`）

### Step 5: 保存完了の報告

保存したファイルパスをユーザーに報告する。対応するplanファイルがある場合はその旨も伝える。

## 重要なルール

- テンプレートの構造を変更しない。セクションの順序と見出しを維持する
- 内容は具体的に書く。曖昧な記述（「いくつかの変更を行った」など）は避ける
- 備考セクションは補足がなければ省略してよい
